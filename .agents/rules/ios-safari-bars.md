# iOS Safari Top & Bottom Bars (Mobile Edge-to-Edge)

When styling full-screen map, canvas, or overlay layouts for mobile iOS Safari (`@media (max-width: 760px)` with `viewport-fit=cover`):

1. **Avoid `<meta name="theme-color">` When Top and Bottom Bars Need Different Treatments**:
   - Do not use a static `<meta name="theme-color">` tag if the top status bar needs a tint (`--surface-soft` `#f5f2eb`) while the bottom Safari toolbar should remain translucent over the map or menu.
   - Instead, place a `position: fixed; inset: 0 0 auto;` strip at the top edge (e.g. `.app-header::after` and `.detail-overlay::before` with `height: max(4px, env(safe-area-inset-top, 0px))` and solid `background-color: var(--surface-soft)`) so WebKit's `PageColorSampler` tints only the top status bar, followed by a `68px` linear gradient (`.app-header::before`) from `var(--surface-soft)` to transparent.

2. **Stretch Full-Screen Map & Overlays Past `100lvh` into the Bottom Safe Area Across ALL Mobile States**:
   - In iOS Safari, `100lvh` excludes the `34px` bottom home-indicator safe area (`env(safe-area-inset-bottom)`), and `env(safe-area-inset-bottom)` can report `0px` while the floating toolbar is expanded—leaving a `34px` gap at the bottom if elements use `height: 100lvh`.
   - Set `body` to `min-height: 100dvh; height: calc(100lvh + max(34px, env(safe-area-inset-bottom, 0px))) !important;` (with `html { height: 100%; }`), and stretch `#map`, `.monks-panel`, and `.detail-overlay` using `position: absolute; top: 0; right: 0; bottom: 0; left: 0; height: auto;` rather than `position: fixed` or a strict `height: 100lvh`.
   - Do not apply downward `translateY` transforms to full-bleed `bottom: 0` containers (like `.monks-panel`), as that pushes their layout overflow box below `body`; animate their inner children instead.

3. **Keep Root & Map Backgrounds Transparent Across All Mobile States (Including "View map" Hidden-UI State)**:
   - Keep `html, body, #map { background-color: transparent !important; }` across **all** mobile states (`default map`, `View map / hidden UI` `body.map-only-view`, `open menu` `body.mobile-list-open`, `small place card` `#mobile-card-overlay`, `monk detail sheet` `body.monk-modal-open`, and `edition/introduction` `.is-intro`). Never set a solid fallback `background-color` on `html` or `body` when switching states, as Safari's bottom-bar sampler will paint a solid rectangular band in the bottom safe area.
   - When hiding bottom-anchored `position: fixed` UI in the `"View map"` (`body.map-only-view`), menu, or modal states (e.g. `#mobile-card-overlay` at `bottom: calc(16px + env(safe-area-inset-bottom))`), **never** translate the element down to `bottom: 0` (within 3px of the bottom viewport edge) or leave it `visibility: visible` with `opacity: 0`. Use a smaller offset (`transform: translateY(8px)` so it stays >= 8px above the bottom edge) and transition `visibility: hidden` so Safari's bottom-bar color sampler never samples the hidden card's background.
   - In `open menu` (`.monks-panel`) and `monk detail sheet` / `introduction` (`.detail-overlay`), apply the surface background (`--surface-base` or `--surface-soft`) and progressive bottom blur (`::after` with `backdrop-filter: blur(12px)`) directly on the full-bleed `position: absolute; top: 0; right: 0; bottom: 0; left: 0;` overlay container extending into `max(34px, env(safe-area-inset-bottom, 0px))`.
